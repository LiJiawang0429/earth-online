# 产品概述

## 背景与问题

现代都市人的生活正在加速「NPC 化」：两点一线、重复通勤、算法投喂、周末躺平。当一个人的行为模式可以被精准预测、每天的差异小于 5% 时，他在自己的人生里更像一个按脚本运行的非玩家角色，而非主动探索世界的主角。

这种「NPC 感」的本质不是忙，而是**缺乏玩家能动性（Player Agency）**——行为由外部条件驱动而非主动选择，重复动作没有成长反馈，生活半径固化导致对周围世界的变化毫无感知。

## 产品愿景

**把现实世界变成一个可交互的开放世界游戏，让每个人重新成为自己人生的主角。**

地球Online 不是又一个打卡工具或任务清单，而是一层叠加在真实世界之上的「游戏化感知层」：它同步现实世界的信息，用 AI 为每个用户生成专属的每日任务，用成长系统和探索机制奖励打破常规的行为，最终让「活着」从被动循环变成主动冒险。

## 产品定位

|维度|定义|
|---|---|
|一句话定位|基于现实世界信息的 AI 驱动开放世界生活游戏|
|核心价值|用游戏化机制对抗生活的重复感，提供具体可执行的「打破常规」灵感与成长反馈|
|产品形态|单机优先的 Web App（PWA），用户自带 API Key；后续可扩展为移动端 App|
|差异化|任务不是预设模板，而是 AI 结合「你是谁 \+ 你在哪 \+ 世界正在发生什么」实时生成；世界信息与现实同步，重点探索「探坑」（非热门、隐藏、在地化体验）|
|商业模式|MVP 阶段免费 \+ 用户自带 API Key；后期可推出托管版订阅、商家合作、城市主题包|

## 目标用户

|用户分层|画像|核心痛点|
|---|---|---|
|核心用户|22\-35 岁都市白领，一二线城市，对生活有热情但被工作消耗|周末不知道干嘛、生活半径小、想改变但缺乏具体灵感和行动力|
|扩展用户|大学生、自由职业者、新城市移民|对所在城市不熟悉、社交圈窄、需要探索外部世界的契机|
|潜在用户|旅行爱好者、City Walk 玩家、猎奇体验追求者|常规攻略太同质化，想要更个性化、更在地的探索指引|

# 第一性原理与人性需求

## 问题本质拆解

回到第一性原理：人为什么会觉得自己像 NPC？逐层拆解：

1. **缺乏自主选择**：每天的行为由工作时间、通勤路线、生存需求决定，「我今天要做什么」这个问题的答案是预设的。

2. **缺乏有意义的反馈**：重复行为不产生成长感——走同样的路、吃同样的饭、见同样的人，没有「升级」或「解锁」的体验。

3. **缺乏世界感知**：生活半径固化（家\-公司\-常去的几家店），对周围 1 公里内新开的店、正在发生的活动、隐藏的角落毫无察觉。

4. **缺乏叙事感**：人生没有「主线剧情」，日子是离散的重复单元而非连续的成长故事。

因此，解决方案的本质不是「加更多功能」，而是**重建这四种感知**：让用户重新拥有选择权、获得成长反馈、感知真实世界、构建人生叙事。

## 人性需求与玩法映射

每一个玩法设计都必须对应一个真实的人性需求，而非「游戏里有这个所以我们也要有」。

|人性需求|心理学依据|对应玩法|
|---|---|---|
|自主感|自我决定理论（SDT）：自主是内在动机的核心|每日任务提供多选项、可刷新、可自定义主线目标；任务是「建议」而非「强制」|
|胜任感|SDT：能力感知驱动持续行为|角色等级、属性成长、技能树、成就徽章；任务难度分级，确保「跳一跳够得着」|
|关联感|SDT：与世界和他人的连接是幸福感来源|世界信息同步、地点探索、留言瓶（后期）、附近玩家（后期）|
|好奇心|信息缺口理论：未知产生探索欲望|探索迷雾地图、随机事件、彩蛋、「探坑」推荐、地球图鉴收集|
|意义感|叙事心理学：人通过故事理解人生|主线任务链、主角传记（AI 生成人生叙事）、时间线回顾、章节制资料片|
|收集欲|收藏家本能：集齐与分类带来秩序感|地球图鉴（地点/食物/体验）、徽章墙、稀有度系统|
|成就感|目标设置理论：具体目标 \+ 即时反馈 = 高绩效|每日任务完成、连续打卡、世界 Boss 挑战、副本通关评分|
|表达欲|自我呈现理论：人需要记录和分享体验|任务感想记录（文字/语音/图片）、个人时间线、可导出的「人生冒险日志」|

**设计红线**：任何玩法如果不能对应上表中的至少一项人性需求，就不做。避免「为了游戏化而游戏化」的功能堆砌。

# 产品核心循环

地球Online 的所有功能围绕一个核心循环运转：

这个循环的关键在于：**每一次循环都让用户和「世界」同时发生变化**——用户在成长（等级、属性、图鉴），世界也在更新（新的探索区域、新的事件、更高难度的任务）。这正是开放世界游戏让人上瘾的核心机制，而我们把它叠加在了现实世界之上。

# 核心玩法体系

以下玩法分为「用户原始构想」和「补充玩法」两部分，共同构成完整的玩法体系。

## 用户原始构想（已确认）

### 虚拟主角系统

每个用户拥有一个虚拟分身，代表「现实中的你」在游戏中的投影。

- **角色卡**：等级、称号、五维属性（体力、智力、魅力、勇气、创造力）

- **状态同步**：现实行为映射到角色状态——今天走了 8000 步→体力经验 \+；学了一道新菜→创造力经验 \+；和陌生人交谈→魅力经验 \+

- **外观解锁**：等级提升或完成特定成就解锁角色外观、头像框、称号

### 现实世界信息同步

世界不是静态地图，而是与现实同步的「活的开放世界」。

- **位置感知**：基于 GPS 获取周边 POI、新店开业、限时活动、展览市集

- **环境同步**：实时天气、季节、日出日落、节假日

- **探索迷雾**：地图上未去过的区域显示为迷雾，实际到达后点亮，形成「我的城市足迹」

- **探坑重点**：AI 重点挖掘非热门、隐藏、在地化的体验——胡同里的旧书店、社区菜市场、楼顶观景台、深夜面馆等

### AI 每日 Online 任务

每天 AI 结合用户实际情况和周围世界信息，生成专属任务。这是产品的核心引擎，详见第 5 章。

### 任务感想记录

完成任务后记录感想，不是简单的「打卡」，而是构建人生叙事的素材。

- 支持文字、语音、图片三种记录方式

- AI 自动从感想中提炼「成长关键词」和「情绪曲线」

- 所有记录汇入个人时间线，可按时间、地点、任务类型回溯

## 补充玩法（PM 建议新增）

### 反 NPC 指数与觉醒机制

**对应需求**：自主感、意义感

这是产品的「灵魂功能」——直接回应「活着像 NPC」的核心痛点。

- **NPC 指数计算**：基于用户行为数据（通勤路线重复度、常去地点数量、新体验频率、任务完成多样性）每日/每周计算一个 0\-100 的「NPC 指数」，分数越高表示生活越重复

- **可视化**：生活热力图（哪里去得最多）、重复路径识别、本周 vs 上周的「新鲜度对比」

- **觉醒干预**：当 NPC 指数连续 3 天超过阈值（如 75），触发「觉醒事件」——AI 生成一个专门设计来打破常规的任务（如「今天下班换一条完全不同的路线回家，沿途记录 3 个之前没注意到的细节」）

- **觉醒成就**：成功降低 NPC 指数获得「觉醒者」称号和额外经验奖励

### 现实技能树

**对应需求**：胜任感、成就感

- **技能分类**：烹饪、语言、运动、艺术、社交、手工、自然探索、城市文化等 8 大系

- **节点解锁**：完成相关任务获得技能点，投入技能树解锁节点（如「烹饪」系：煮蛋→炒饭→烘焙→地方菜→创意料理）

- **技能影响任务**：解锁高阶技能后，AI 会生成对应更高难度、更专业的任务（如解锁「咖啡品鉴」后，任务可能是「盲测 3 家店的手冲咖啡并写出风味描述」）

- **技能等级认证**：达到一定等级可获得「地球Online 认证」，解锁专属称号和外观

### 地球图鉴与稀有度系统

**对应需求**：收集欲、好奇心、成就感

- **图鉴分类**：地点（去过的地方）、美食（吃过的特色食物）、体验（做过的事）、人物（遇到的有趣的人）、事件（参与过的活动）

- **稀有度分级**：普通（连锁餐厅、热门景点）、稀有（独立小店、本地市场）、史诗（隐藏地点、限定活动）、传说（极难遇到的体验，如凌晨 4 点的海边日出、百年老店的隐藏菜单）

- **图鉴完成度**：按城市、分类、稀有度统计完成度，驱动探索

- **探坑图鉴**：专门的「探坑」分类，鼓励用户发现和记录非热门体验，AI 会优先推荐未被收录的地点

### 随机事件与世界彩蛋

**对应需求**：好奇心、惊喜感

- **位置触发**：路过特定类型地点时触发随机事件——路过书店→「随机抽一本书翻到第 37 页，读一段话并记录感受」；路过公园→「找一个长椅坐 5 分钟，闭上眼睛数 3 种不同的声音」

- **天气联动**：下雨天→「找一个有窗的位置，点一杯热饮，听一首对应天气的歌」；下雪天→「在雪地里走 10 分钟，不看手机」；大风天→「找一个避风的角落观察风吹过的痕迹」

- **时间彩蛋**：深夜（23:00 后）解锁「夜行任务」；清晨（6:00 前）解锁「追日出任务」；特定日期（生日、节日、纪念日）触发专属事件

- **世界 Boss**：城市级限时挑战（如「本周内找到 3 家没有招牌的店」「一天内用 3 种不同的交通方式出行」），全服（后期）或个人进度追踪

### 主线剧情与章节制资料片

**对应需求**：意义感、叙事感

- **主线设定**：用户在初始化时设定 1\-3 个人生目标（如「今年学会冲浪」「读完 20 本书」「认识 10 个不同行业的人」），AI 将其拆解为主线任务链

- **章节制**：每 3 个月为一个「资料片」季度，AI 回顾用户上一季度的成长，生成「季度传记」，并开启下一季度的主题（如 Q1「觉醒之春」、Q2「盛夏冒险」、Q3「收获之秋」、Q4「冬日内观」）

- **剧情分支**：用户的选择和行为会影响主线走向——总是选择社交任务→主线偏向「社交达人」线；总是选择探索任务→主线偏向「世界探索者」线

- **里程碑事件**：完成主线关键节点触发「里程碑」，生成专属纪念卡片和大幅经验奖励

### 现实副本与主题探索

**对应需求**：成就感、好奇心、社交（后期）

- **副本类型**：周末半日/一日探索路线，按主题分类——美食副本（「老城小吃巡礼」）、艺术副本（「街头涂鸦地图」）、自然副本（「城市绿道徒步」）、历史副本（「百年建筑漫步」）、猎奇副本（「城市废墟探索」）

- **副本结构**：起点→3\-5 个任务节点→终点，每个节点有具体任务和探索提示

- **评分系统**：完成时间、任务完成度、隐藏路线发现、感想质量综合评分（S/A/B/C）

- **隐藏路线**：每个副本有 1\-2 条隐藏路线，需要在探索中发现线索才能解锁

- **AI 生成副本**：后期可让 AI 根据用户位置和兴趣动态生成专属副本

### 环境扫描与世界叙事

**对应需求**：好奇心、意义感

- **扫描功能**：用户对准周围建筑/街道/店铺，AI 结合位置信息生成沉浸式描述——历史背景、建筑故事、在地趣闻、隐藏细节

- **世界描述**：每个被探索的地点都有一段 AI 生成的「世界叙事」，类似游戏中的地点描述文本，让普通的街角也有故事感

- **城市传说**：收集和生成城市传说、都市怪谈、本地故事，用户可在特定地点触发「传说任务」

### 社交系统（后期，非 MVP）

**对应需求**：关联感、表达欲

- **留言瓶**：在某个地点留下感想/建议，其他玩家到达该地点时可以看到（类似现实版的「时空胶囊」）

- **附近主角**：隐私保护前提下，看到附近其他玩家的位置和状态（只显示「距离你 500 米有一个正在探索的主角」）

- **组队任务**：多人协作完成现实挑战（如「两人分别从城市两端出发，在中间点汇合，各记录沿途 5 个有趣发现」）

- **好友启发**：不是竞争排行榜，而是「你的朋友这周做了这件事，要不要也试试？」的轻量社交推荐

**玩法优先级说明**：以上 8 项补充玩法中，「反 NPC 指数」「现实技能树」「地球图鉴」「随机事件」为高优先级（MVP 或 v1\.0 纳入）；「主线剧情」「现实副本」「环境扫描」为中优先级（v1\.x 迭代）；「社交系统」为低优先级（v2\.0\+，需要用户基数支撑）。

# AI 每日任务生成机制（核心引擎）

AI 任务生成是地球Online 的核心竞争力——任务不是预设模板，而是实时结合多维信息动态生成。以下为完整机制设计。

## 生成流程

## 输入维度详解

|维度|数据来源|对任务生成的影响|
|---|---|---|
|用户画像|初始化问卷 \+ 行为累积|兴趣匹配（喜欢美食→美食任务多）、能力适配（不会做饭→从简单任务开始）、避免重复（上周做过类似的→换类型）|
|世界状态|GPS \+ 天气 API \+ 日历 \+ POI|位置相关（推荐附近的店/活动）、天气适配（雨天→室内任务，晴天→户外任务）、时间节奏（工作日→短时任务，周末→长时任务）、节日联动|
|成长目标|用户设定 \+ 技能树 \+ 图鉴|主线任务围绕目标设计、技能点投入方向影响任务类型、图鉴缺口驱动探索任务|
|反 NPC 检测|行为数据分析|NPC 指数高→优先生成「打破常规」类任务；生活半径小→推荐更远的探索任务；任务类型单一→强制换品类|

## 每日任务结构

每天生成 3 个任务，各司其职：

|任务类型|定位|预计耗时|设计逻辑|
|---|---|---|---|
|主线任务|推进人生目标|30 分钟 \- 半天|围绕用户设定的主线目标拆解，确保每天都有一步朝着目标前进。如目标「学摄影」→ 主线「今天用手机拍 10 张阴影主题的照片」|
|探索任务|感知真实世界|15 分钟 \- 2 小时|结合位置和世界信息，推荐周边的探索体验，重点是「探坑」。如「你公司 800 米外有一家开了 20 年的老面馆，中午去试试，和老板聊一句」|
|随机任务|打破常规 / 惊喜|5 \- 30 分钟|轻量、有趣、出人意料，降低执行门槛。如「今天对 3 个陌生人微笑」「在通勤路上换一首从未听过的音乐类型」|

## 任务生成 Prompt 策略

LLM 调用采用结构化 Prompt，核心约束如下：

- **具体可执行**：任务必须有明确的动作和完成标准，禁止「享受生活」「放松一下」这类模糊描述

- **与用户相关**：必须引用用户画像中的至少一个特征（兴趣/位置/目标），让用户觉得「这是给我的」

- **与世界相关**：必须结合当前位置/天气/时间中的至少一个维度

- **难度适配**：根据用户等级和历史完成率调整难度，新用户从轻松任务开始

- **安全合规**：禁止生成危险、违法、侵犯他人隐私的任务

- **多样性**：连续 7 天内任务类型不重复超过 2 次

## 任务刷新与放弃机制

- **有限刷新**：每个任务每天可刷新 1 次（防止用户无限刷简单任务），刷新后从备选池替换

- **合理放弃**：任务可标记「今日不做」，不扣分，但连续放弃同一类型任务会触发 AI 询问「是不是对这类任务不感兴趣？」并调整后续生成

- **延期机制**：任务可延期到明天，但延期的任务经验减半（鼓励当日完成）

# 世界信息同步机制

## 信息层级

|层级|内容|更新频率|
|---|---|---|
|环境层|天气、温度、日出日落、季节、空气质量|实时（每小时）|
|地理层|周边 POI、新店、关闭店、评分变化|每日更新|
|事件层|展览、市集、演出、限时活动、节日|每日更新 \+ 提前 3 天预告|
|探坑层|隐藏小店、非热门景点、在地体验、用户贡献的「坑」|AI 挖掘 \+ 用户贡献，持续累积|
|叙事层|地点故事、城市传说、历史背景（AI 生成）|用户探索时按需生成|

## 探坑信息的获取策略

「探坑」是产品差异化重点，但热门地图 API 的 POI 数据偏向商业化地点，隐藏体验需要特殊策略：

1. **AI 挖掘**：LLM 结合位置信息，从公开信息（社交媒体、本地论坛、旅游博客）中挖掘非热门地点，生成「探坑推荐」

2. **反向筛选**：在 POI 数据中筛选评分高但评论数少的地点（「高评分低热度」= 可能的宝藏地点）

3. **用户贡献**：用户完成探索任务后可标记「这是一个坑」，经 AI 审核后加入探坑库（后期社交功能）

4. **类型偏移**：优先推荐菜市场、老社区、独立书店、手工工坊、楼顶空间、废弃铁路改造区等非常规旅游类型

# 成长与反馈系统

## 经验与等级

- **经验获取**：完成任务获得经验，任务难度越高经验越多（随机任务 10\-30，探索任务 30\-80，主线任务 50\-150，副本 100\-300）

- **等级体系**：1\-100 级，每级所需经验递增（参考 RPG 曲线），等级影响解锁内容和任务难度上限

- **五维属性**：体力、智力、魅力、勇气、创造力，每个任务完成后根据任务类型增加对应属性 1\-5 点

- **属性影响**：属性达到阈值解锁特殊任务和称号（如勇气 50\+ 解锁「深夜探索」类任务）

## 成就与称号

- **成就分类**：探索类（「点亮 100 个地点」）、坚持类（「连续 30 天完成任务」）、勇气类（「第一次和陌生人交谈」）、稀有类（「发现传说级体验」）

- **称号系统**：成就解锁称号，可装备在角色卡上展示（如「城市探坑家」「深夜行者」「百日觉醒者」）

- **里程碑**：等级 10/25/50/75/100 触发里程碑事件，生成专属纪念内容

## 回顾与叙事

- **日报**：每晚自动生成「今日冒险摘要」——完成了什么、去了哪里、属性增长、NPC 指数变化

- **周报**：每周生成「本周冒险报告」——任务完成率、新探索地点、NPC 指数趋势、AI 点评和下周建议

- **主角传记**：每季度 AI 根据用户的任务记录和感想，生成一段 500\-1000 字的「人生叙事」，用第二人称讲述这一季度的冒险故事

- **时间线**：所有任务、感想、地点按时间排列，可按地图/类型/情绪筛选浏览

## 技术选型建议

|层级|选型|理由|

## API Key 接入方案

用户自带 API Key 是单机版的核心设计决策——降低运营成本、保护隐私、让用户对自己的数据有完全控制权。

### 需要接入的 API

|API 类型|推荐服务|调用频率|用途|
|---|---|---|---|
|LLM|OpenAI / Anthropic / 字节豆包 / DeepSeek|每日 3\-5 次|任务生成、感想分析、日报/周报、世界叙事|
|地图/POI|高德地图 API / 百度地图 API|每日 2\-3 次|周边 POI 查询、地理编码、地点详情|
|天气|和风天气 / OpenWeatherMap|每日 1 次|实时天气、未来 24 小时预报|

### Key 管理设计

- **本地存储**：API Key 仅存储在浏览器本地（IndexedDB 加密存储），不上传任何服务器

- **直连模式**：客户端直接调用第三方 API，不经过中间服务器（避免中转成本和隐私风险）

- **Key 配置向导**：首次使用时引导用户输入各 API 的 Key，提供获取 Key 的教程链接

- **用量预估**：在配置页面显示「预计每日 API 调用成本」（基于平均调用量和各 API 定价），让用户有预期

- **降级方案**：如果用户只配置了 LLM Key 而没配置地图/天气 Key，任务生成退化为「不基于位置和天气」的通用模式，保证核心功能可用

### API 调用成本估算（单用户/月）

|API|日调用|月调用|预估费用|说明|
|---|---|---|---|---|
|LLM（GPT\-4o mini 级）|4 次|120 次|约 ¥5\-15|取决于输入输出 token 量，任务生成 Prompt 约 1\-2k token|
|地图 POI|2 次|60 次|免费额度内|高德/百度个人开发者每日有免费额度|
|天气|1 次|30 次|免费额度内|和风天气个人版每日 1000 次免费|
|**合计**|7 次|210 次|**约 ¥5\-15/月**|主要成本在 LLM，使用低价模型可进一步降低|

# 风险、伦理与开放问题

## 风险与应对

|风险|影响|应对策略|
|---|---|---|
|API Key 配置门槛高|非技术用户流失，初始化完成率低|提供图文/视频教程；支持「一键导入」配置模板；考虑后期推出托管版（平台代付 API 费用，用户订阅）|
|AI 生成任务质量不稳定|任务不可执行、不相关、重复，用户失去信任|任务校验器（规则过滤 \+ LLM 自检）；用户反馈机制（「这个任务不好」→ 微调 Prompt）；建立任务质量评分体系|
|隐私与位置数据|位置数据敏感，用户担忧隐私|纯单机架构，所有数据本地存储，不上传服务器；位置信息仅用于 API 调用；明确隐私政策，用户可随时清除数据|
|游戏化疲劳|用户把任务当成负担，产生逆反心理|任务是「建议」而非「强制」；可随时暂停；NPC 指数设计为自我觉察工具而非批评；避免过度通知和催促|
|「探坑」信息准确性|AI 推荐的地点已关闭或信息错误|POI 数据交叉验证（多源比对）；用户可标记「地点不存在」；AI 生成的探坑标注「信息需核实」|
|用户安全|探索任务可能引导用户去不安全的地方|任务生成时加入安全约束（避免深夜偏僻地点、危险区域）；危险任务添加安全提示；用户可设置「安全模式」限制探索范围|

## 伦理考量

- **不制造焦虑**：NPC 指数是自我觉察工具，不是评判标准。设计上避免「你很失败」的暗示，而是「这里有一个改变的机会」。

- **不替代真实生活**：产品目标是让人更投入现实，而非更沉迷手机。任务设计鼓励「放下手机去体验」，感想记录在体验完成后进行。

- **数据自主权**：单机模式下用户对自己的数据有完全控制权，可导出、可删除、可迁移。

- **避免算法茧房**：AI 任务生成需要刻意引入「用户兴趣之外」的随机任务，防止把用户困在自己的偏好里——这本身就和「打破 NPC 循环」的目标矛盾。

## 开放问题（待决策）

1. **LLM 模型选型**：默认推荐哪个模型？需要在任务质量和成本之间权衡。建议 MVP 阶段支持多模型切换，让用户自选。

2. **地图服务选择**：国内用高德还是百度？海外用户如何支持？MVP 先支持国内，海外留接口。

3. **是否需要账号系统**：纯单机意味着换设备数据丢失。是否在 MVP 后加入「数据导出/导入」功能，作为轻量同步方案？

4. **通知策略**：每日任务生成后是否推送通知？推送频率和时间如何设定？过多通知会导致卸载，不推送可能导致遗忘。

5. **「探坑」的内容审核**：后期用户贡献探坑地点时，如何审核内容质量和安全性？是否需要人工审核还是 AI 审核即可？

6. **monetization 时机**：何时引入付费功能？托管版订阅的定价策略？建议在 v1\.0 验证留存后再考虑商业化。

**总结**：地球Online 的核心赌注是——当现实世界被赋予游戏化的「任务\-反馈\-成长」循环，并且 AI 能真正理解「你是谁、你在哪、世界正在发生什么」时，人们会愿意从被动循环走向主动探索。MVP 阶段用最小成本验证这个核心假设：AI 生成的任务是否真的能让人打破常规？完成任务后的感想和成长反馈是否能形成持续的使用习惯？如果这两个问题的答案是肯定的，后续的玩法丰富化和社会化才有意义。
